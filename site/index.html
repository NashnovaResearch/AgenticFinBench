03 / METHODOLOGY

从完整回答，到可追溯的评分。

提交参评模型的回答与原始 Trace，流水线逐题衔接各个阶段，保留中间结果和判断依据。

  1. 01

    提交回答

    准备题号、完整回答和可选的原始工具 Trace，绑定冻结题面。

    JSONL / JSON
  2. 02

    抽取事实原子

    将回答拆成可核验的主张，保留对象、时间、单位与语境。

    DeepSeek v4.1 Flash
  3. 03

    v3 证据核验

    Agent 先查 Trace，再按需搜索原文与计算，保留两轴判定。

    DSH · DeepSeek v4 Flash
  4. 04

    Rubric 质量评分

    读取完整正负项和核验证据，逐项判定，程序计算质量分。

    DeepSeek v4.1 Flash
QUALITY / 质量轴

奖励完整回答，扣除实质错误。

正向项二元判定，权重合计 100 分。负向项明确触发才扣分，同一根因避免重复扣罚；关键错误导致必要计算或结论失效时，检查依赖关系并应用相应封顶。

EVIDENCE / 证据轴

有来源，不代表事实一定正确。

Trace 或外部事实任一支持，计入综合证据支持。事实反驳仍独立保留，并交给质量评分检查影响。未核实不自动等于错误，政策通过率也不等于事实正确率。

模型需要自己生成回答吗？

需要。这个评测包读取已生成的回答；你可以用任意模型或 Agent 答题，再按题号提交 JSONL。没有 Trace 也可进行事实核验，但 Trace 轴会记录不完整。

可以断点续跑吗？

再次执行同一命令会校验输入和版本，复用已经成功的阶段。改动回答、配置或评分协议时，请使用新的输出目录。

在哪里看逐题结果和总平均分？

运行时终端展示逐题进度；输出目录的 scores.csv 保存逐题分数，summary.json 保存质量平均分、完成分母和失败数。未完成整套题时，结果会明确标为阶段性成绩。
